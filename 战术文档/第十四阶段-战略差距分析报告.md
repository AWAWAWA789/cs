## 前端功能评估

已交付的浏览器界面覆盖了战略目标 G7 的核心要求：K 线可视化、情景概率条、交易建议卡片、相似历史片段列表、模板匹配卡片、浪形草图 SVG 与 LLM 解释面板。接口支持手动刷新与 5 分钟定时刷新，子指数从后端 `/scenario/meta` 动态发现。

存在的可完善点：

- **错误边界不足**：当 `/scenario/generate` 或 `/scenario/explain` 返回 500 时，界面仅显示单行错误文本，没有重试或降级展示。
- **加载状态缺失**：多个面板同时异步加载，用户无法感知单个面板的加载进度。
- **回测可视化未接入**：P2 目标中的净值曲线、交易点位图尚未在前端落地。
- **浪形草图可读性**：当前 SVG 仅按点序列连接，未按价格排序，极端情况下折线可能前后交叉。
- **参数调节未暴露**：模板置信度阈值、近邻数等参数仍通过后端默认值固定，用户无法在界面实验。

## 算法代码审查结果

本次审查未发现会导致崩溃或输出格式错误的严重 bug，但定位到以下影响校准质量的设计与精度问题：

### 1. 贝叶斯似然按方向聚合，颗粒度不足

`bayesian_calibration.py` 的 `build_evidence_histogram` 仅按 `bullish / bearish / neutral` 三个方向统计似然，没有区分具体情景（如“上涨延续”与“先跌后涨”均为 bullish）。这导致不同 bullish 情景共享同一似然，后验概率无法反映模板差异。

### 2. 似然计数截断造成精度损失

`calibrate_probabilities` 中：

```python
occurred = int(raw_likelihood * total)
```

当 `raw_likelihood * total` 非整数时直接截断，会系统性地压低或抬高发生次数，进而扭曲似然。

### 3. 温度缩放未按子指数区分

当前 `temperature=0.8` 为全局固定值。Phase 14 Brier 报告显示贴纸（0.234）与百元主战（0.491）校准表现差异巨大，说明同一温度无法适配不同子指数的置信度分布。

### 4. 买入持有基准缺失

`reports/glove_trend_following_walkforward.json` 仅给出策略收益，没有同期买入持有净值，G2 的“超额收益”指标无法验证。

### 5. 测试覆盖存在缺口

现有测试未覆盖：

- `source` 字段最终输出合法性（`similarity/template/fusion/fallback` 四选一）；
- 价格尺度异常回归（确保 support/resistance 与 current close 同周期）；
- 子指数级 Brier 校准是否收敛；
- 前端端到端加载与交互路径。

## 优化改进方案

### 方案一：子指数级温度自适应校准

为每个子指数维护独立的温度参数，通过 walk-forward 最小化该子指数的 Brier 分数。实现方式：

- 在 `bayesian_calibration.py` 中新增 `temperature_grid`，对训练窗口按子指数搜索最优温度；
- 将最优温度持久化到 `data/calibration/<sub_index>_temperature.json`；
- 推理时优先读取该子指数的温度，未命中时回退到全局默认值。

预期效果：百元主战与手套的过度自信问题可显著缓解，聚合 Brier 向 0.25 靠近。

### 方案二：引入真实未来收益标签并周期性重校准

当前 Brier 报告基于历史 walk-forward 结果，但生产环境需要持续累积真实未来价格：

- 建立 `CalibrationStore`，每日记录 `{sub_index, period, predicted_scenario, probability, future_return_5, future_return_7}`；
- 每周运行一次重校准任务，重新估计方向级似然与温度；
- 似然计算从方向级升级到情景键级（`scenario_key` 区分具体情景）。

预期效果：打破“一次性校准”假设，使概率随市场机制变化而自适应。

### 方案三：修复似然计数精度

将 `int(raw_likelihood * total)` 替换为更平滑的估计：

```python
occurred = raw_likelihood * total  # 保留浮点
likelihood = (occurred + laplace_alpha) / (total + 2 * laplace_alpha)
```

避免截断带来的系统性偏差。

### 方案四：建立买入持有基准

新增 `src/analysis/buy_and_hold.py`：

- 输入子指数与时间段，计算买入持有累计收益、最大回撤、夏普；
- 在回测报告与 walk-forward 报告中附加 `buy_and_hold_return` 与 `excess_return`；
- 为 G2 验收提供可量化依据。

### 方案五：补齐测试与前端监控

- 新增 `test_source_field.py`，断言所有输出情景的 `source` 在合法集合内；
- 新增 `test_price_scale_regression.py`，断言 `support < current_close < resistance` 在方向非中性时成立；
- 前端增加全局错误边界、面板级 skeleton 加载态，并接入 `/scenario/meta` 参数调节原型；
- 引入 Playwright 或 lightweight 的 jsdom 测试，覆盖页面初始化与刷新路径。
